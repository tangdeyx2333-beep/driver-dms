# 驾驶疲劳检测与预警系统：系统总览

> 状态：独立评审通过，用户已于 2026-11-17 确认。本文件定义系统目标、能力边界和运行逻辑；不作为具体需求的实现授权。现有 `requirements/overview.md` 中的需求顺序与技术候选，将用于编写正式 Roadmap。

## 1. 课题目标与适用边界

本课题设计一套运行于 Windows 个人计算机的桌面原型。系统从普通摄像头取得画面，以 YOLO 在主检测链路中定位人脸，提取眼部和头部相关特征，分析疲劳相关行为，判断风险并通过界面和声音提醒。系统还应支持本地、可重复的实验输入，以便核对检测过程并形成有依据的实验分析和论文材料。

系统用于静止环境下的毕业设计研究、实验和演示。它识别的是画面中预设的疲劳相关行为及其风险，不能据此证明驾驶员的真实生理疲劳，更不承担实际道路安全保障。核心运行链路在本机完成；视频、模型推理和判断不依赖云端服务或视频上传。

系统不涉及车辆控制与车载通信、身份识别、云端部署、大规模训练平台或从零设计深度学习网络。历史预警记录和个体自适应参数属于候选增强能力，不计入当前必做闭环。

## 2. 系统能力模型

| 能力 | 职责与可观察结果 | 与其他能力的关系 |
|---|---|---|
| 输入与运行控制 | 接收摄像头画面及本地可重复实验输入；提供启动、停止和输入状态 | 向视觉检测提供连续、可追溯的画面；输入失效时通知状态管理 |
| YOLO 人脸定位 | 在画面中定位供分析的目标人脸，并报告未检出或结果无效 | 是面部特征提取的上游；不能由后续关键点模块绕过该定位结果独立形成主链路 |
| 面部特征提取 | 在有效人脸区域内取得眼部与头部相关特征，并标明有效性 | 为时序分析提供特征；特征不足时阻止无依据的风险结论 |
| 疲劳行为分析 | 结合眼睛开闭、持续闭眼、PERCLOS 及头部姿态，形成可解释的行为依据 | 消费有效特征及其时间关系；向风险判断提供依据而不直接操作预警 |
| 风险判断 | 区分正常、轻度风险、严重风险和检测不可用等状态 | 只根据有效分析依据给出风险；异常状态不能冒充疲劳风险 |
| 声光预警与展示 | 展示画面、检测依据、运行状态和风险；按风险状态提供视觉和声音反馈 | 消费风险与异常状态；用户的控制操作返回运行控制 |
| 实验与评价 | 使用可重复输入、人工依据及运行结果评估检测效果、误报漏报和响应表现 | 对系统能力给出可检查证据；结果用于论文，不反向伪造系统已达到的性能 |

上述能力是职责划分，不预设具体类、接口、阈值或软件包。YOLO 人脸定位是明确的主链路要求；具体模型、关键点工具、界面框架及参数需要在后续需求和技术验证中确认。

## 3. 关键对象与状态

| 对象 | 含义 | 关键约束 |
|---|---|---|
| 输入源与画面 | 摄像头或本地实验材料及其连续图像 | 应能区分输入中断、画面不可用和主动停止 |
| 目标人脸区域 | YOLO 对当前画面给出的分析目标 | 未检出或目标无法确定时，不向下游传递有效面部结论 |
| 面部特征 | 眼部与头部的观测值及其有效性 | 与对应画面和目标人脸关联；无效观测不得当作正常或疲劳证据 |
| 行为依据 | 由连续观测形成的闭眼、PERCLOS、姿态等分析结果 | 应能追溯其时间范围和有效输入，避免将单帧误判直接等同于疲劳 |
| 风险与运行状态 | 正常、轻度、严重、检测不可用，以及停止、运行、输入异常等运行状态 | 风险等级与运行故障分开表达；状态改变时展示和预警需同步更新 |
| 预警反馈 | 视觉提示和声音提醒 | 由风险状态驱动，并随风险恢复或检测失效调整 |
| 实验记录 | 输入来源、人工标注依据、系统输出及评价结果 | 只记录真实取得的证据，区分模拟行为与真实疲劳 |

## 4. 核心运行逻辑

```text
用户选择输入并启动
|
+-- 读取下一帧画面
    |
    +-- 画面不可用（输入中断、摄像头异常或视频结束）
    |   +-- 标明输入异常或检测不可用，停止使用旧画面更新风险，并解除过期声光预警
    |   +-- 输入恢复或重新选择 -> 重新读取下一帧
    |   +-- 无法恢复或用户停止 -> 停止输入并结束反馈
    |
    +-- 画面可用 -> YOLO 定位目标人脸
        |
        +-- 人脸未检出或目标无效
        |   +-- 标明检测不可用，中止本帧风险判定并清除过期预警
        |   +-- 继续运行 -> 重新读取下一帧；用户停止 -> 停止输入并结束反馈
        |
        +-- 人脸有效 -> 在该人脸区域提取眼部与头部特征
            |
            +-- 眼部基础分析所需特征无效
            |   +-- 标明检测不可用，中止本帧风险判定并清除过期预警
            |   +-- 继续运行 -> 重新读取下一帧；用户停止 -> 停止输入并结束反馈
            |
            +-- 眼部基础分析所需特征有效
                +-- 分析闭眼与 PERCLOS；头部特征有效时纳入辅助依据
                +-- 根据有效行为判定正常、轻度或严重风险
                +-- 更新画面、指标、风险状态及声光反馈
                +-- 继续运行 -> 重新读取下一帧；用户停止 -> 停止输入并结束反馈
```

界面和运行控制贯穿整个链路：界面持续呈现当前画面、有效检测依据、风险或异常状态；用户停止后不再继续分析和提醒。可重复实验输入沿同一分析链路运行，使实验结果能够与实时摄像头流程比较。

## 5. 异常闭环与验证边界

- 摄像头不可用、输入中断或视频结束时，系统应明确反馈输入状态，停止基于旧画面的风险更新；恢复输入或停止后形成可理解的终态。
- 未检出人脸、目标不明确、眼部基础分析所需关键点无效或图像条件不足以完成眼部分析时，应标明检测不可用，不把缺失数据判为正常，也不凭空提高疲劳风险。头部姿态特征单独失效时，只是不将其纳入辅助依据；多人画面的目标选择规则留待对应需求确认。
- 头部姿态作为辅助依据；姿态数据失效时不得仅凭失效事实提升风险。眼部数据与头部数据部分有效时如何降级，由风险判断需求明确。
- 声光反馈应与当前风险和运行状态一致，避免状态恢复、停止或检测失效后沿用过期警报。具体重复提醒与解除规则留待需求规格确定。
- 实验应覆盖正常、预设异常行为及关键失效场景，并记录输入、人工判断依据和系统结果。准确率、帧率、响应时间及阈值须经目标设备和样本实测后确定，不在总览中宣称已达标。
